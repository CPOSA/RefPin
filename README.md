# PinRef — 截图参考工具

> 一个给画画的人用的桌面工具：框选屏幕 → 截图 → 把图钉在所有窗口最上层 → 实时调色相/灰度/透明度，边看参考边画。

---

## 1. 项目定位

**这是什么**：一个 Windows + Mac 桌面小工具，把屏幕上任意一块区域截下来，变成一张始终置顶、可拖动缩放、可调色的浮动参考图。

**为什么做**：画画时需要把参考图钉在画布旁边看。系统自带截图不能置顶，看图软件不能调成灰度看明暗关系。这个工具把「截图 + 置顶 + 调色」合成一件事。

**不做什么**（划清边界，避免越做越大）：
- 不做 iPad / 安卓版。iPad 系统不允许第三方 app 悬浮在别的 app 上层，且 Procreate 自带参考面板，无需重复造轮子。
- 不做图片编辑器。只做「看参考」需要的调节，不做画笔、图层这些。
- 不做云同步、账号系统这些。就是个本地小工具。

---

## 2. 技术栈

| 用途 | 选型 | 说明 |
|---|---|---|
| 编程语言 | Python 3.10+ | 你最熟的语言，学习成本最低。PySide6 的 wheel 要求 3.10 起 |
| 界面 / 窗口 | PySide6 | Qt 官方 Python 绑定，桌面 GUI 主流方案，"置顶"靠它实现 |
| 屏幕抓取 | Qt `grabWindow`（默认）/ mss | 两个后端都实现了，一行切换。mss 跨平台且快，但 macOS Retina 下只有一半分辨率，所以默认用 Qt 的 |
| 图像处理 | numpy + Pillow | 调色相/灰度本质是对像素数字做数学运算，靠这两个库 |

**为什么是这套**：一份代码基本能同时在 Windows 和 Mac 跑；核心概念（置顶窗口、抓屏、像素运算）都是通用知识，将来想换 Electron 等其他框架，迁移的是界面层，核心思路不变。

## 3. 环境搭建

### 为什么要用虚拟环境

虚拟环境（venv）就是给这个项目单独开一个「装库的小房间」。装进去的库只对本项目生效，不会污染你电脑上的全局 Python，也不会和别的项目抢版本。

代价只有一个：每次写代码前要先「激活」它。习惯之后就是一条命令的事。

### 第一次配置（只做一次）

**1）创建虚拟环境**，在项目根目录执行：

```bash
python3 -m venv .venv
```

跑完会多出一个 `.venv/` 文件夹，里面是这个项目专属的 Python 和 pip。

**2）激活它** —— 这一步 Mac 和 Windows 不一样：

Mac / Linux：

```bash
source .venv/bin/activate
```

Windows（PowerShell）：

```powershell
.venv\Scripts\Activate.ps1
```

激活成功的标志：命令行提示符前面出现 `(.venv)`。**这时 `python` 和 `pip` 才指向项目自己的环境。**

**3）装依赖**：

```bash
pip install -r requirements.txt
```

PySide6 体积不小（含 Qt 库约 400 MB，装完 `.venv` 整体约 1.2 GB），第一次装要等几分钟，属正常。

**4）验证装好了**：

```bash
python -c "import PySide6, mss, numpy, PIL; print('环境 OK')"
```

打印出「环境 OK」就说明阶段 0 完成了。

### 日常使用

每次开始写代码，进项目目录后先激活：

```bash
source .venv/bin/activate
```

写完想退出虚拟环境：

```bash
deactivate
```

> 如果你用 VS Code / PyCharm，在编辑器里把解释器选成 `.venv/bin/python`，它就会自动帮你激活，不用每次手敲。

### 几个容易踩的坑

- **忘记激活**：直接 `pip install` 会装到全局环境去，然后你会发现「明明装了却 import 不到」。看到提示符没有 `(.venv)` 就是没激活。
- **`.venv/` 不要提交到 git**：它有 1.2 GB，且换台电脑就失效。已在 `.gitignore` 里排除。别人拿到代码后，按上面步骤自己建一个就行 —— 这正是 `requirements.txt` 存在的意义。
- **Python 版本太低**：PySide6 要求 3.10 起。如果你的 Python 是 3.14，PySide6 需要 6.10 以上版本才有对应的 wheel（`requirements.txt` 里已经约束好了）。

## 4. 核心概念（理解这几个，整个项目就通了）

- **置顶窗口**：给窗口加一个 `Qt.WindowStaysOnTopHint` 标志，Qt 就会替你和操作系统交涉，让窗口浮在最上层。你想要的核心功能，本质就是这一行。
- **无边框窗口**：`Qt.FramelessWindowHint` 去掉标题栏和边框，让浮窗看起来就是一张干净的图。代价是拖动要自己写。
- **抓屏拿到的是像素数字**：mss 抓到的是一堆 BGRA 像素值。调色相、转灰度、改透明度，全都是在这堆数字上做数学运算，然后再显示出来。这是第二阶段的核心。

## 6. 大致代码结构

初期一个文件就够，别过度设计。等阶段 2、3 代码变多了，再按下面拆分：

```
RefPin/
├── .venv/               # 虚拟环境（git 不追踪）
├── .gitignore
├── README.md
├── requirements.txt     # 依赖清单
└── pinref/
    ├── main.py          # 程序入口，启动应用
    ├── overlay.py       # 框选截图的全屏遮罩
    ├── floating.py      # 置顶浮动图窗口 + 拖动/缩放
    ├── controls.py      # 调色控制面板（滑块）
```

`requirements.txt` 和 `.gitignore` 放在项目根目录（Python 项目惯例），代码放 `pinref/` 子目录里。

**拆分原则**：一个文件只干一类事。改调色逻辑就只动 `imaging.py`，不用在几百行里翻找。

## 7. 已知难点与注意事项

- **抓屏拿到的是 BGRA，不是 RGB**：mss 返回的像素，通道顺序是「蓝-绿-红-透明」，和常见的 RGB 是反的。做灰度、色相运算前必须先翻转通道（`arr[:, :, :3][:, :, ::-1]`），忘了这步图会红蓝对调，看起来非常诡异。这是阶段 2 最容易踩的坑。
  好在转成 Qt 显示时反而不用翻：`QImage.Format_RGB32` 在内存里正好就是 BGRA 排列，可以直接把 mss 的数据喂进去。
- **mss 的新旧写法**：网上多数教程写 `mss.mss()`，这个写法在 mss 10.x 已废弃（会报 DeprecationWarning），要改用 **`mss.MSS()`**（大写）。
- **要浮到别的 app 的全屏画面上，app 必须是 accessory 类型** ⚠️ 阶段 1 最难定位的一条，已解决。
  macOS 的全屏 app 独占一个 Space。**`.regular` 类型的 app（有程序坞图标的普通 app）的窗口，永远不会被合成到别人的全屏 Space 上** —— 窗口层级、`collectionBehavior` 怎么设都没用。改成 **accessory** 类型后，什么额外属性都不用设就正常了：
  ```python
  from AppKit import NSApplication, NSApplicationActivationPolicyAccessory
  NSApplication.sharedApplication().setActivationPolicy_(
      NSApplicationActivationPolicyAccessory)
  ```
  代码在 `main.py` 的 `_use_accessory_policy()`，要在 `QApplication` 创建之后调（NSApplication 实例由它创建）。需要 `pyobjc-framework-Cocoa`，`requirements.txt` 里已用 `; sys_platform == "darwin"` 限定只在 macOS 装。
  **代价**：程序坞里没图标、`Cmd+Tab` 也切不到。对这个工具反而合适，但意味着**阶段 3 的全局快捷键是必需品**——否则没有任何方式再次唤起截图。
  **实测过的无效办法，别再走一遍**（都是在 `.regular` 下试的，全灭）：所有窗口标志组合（`Tool` / `Window` / `Popup` / `SplashScreen` / `BypassWindowManagerHint`）、`collectionBehavior = CanJoinAllSpaces | FullScreenAuxiliary`、窗口层级抬到 `CGShieldingWindowLevel`。切成 accessory 后，这些**一个都不需要**（保持 Qt 默认的 level=8、behavior=128 即可，遮罩照样显示、鼠标照样点得中）。
  **为什么难查**：系统全程声称一切正常 —— `CGDisplayIsAsleep=False`、`IsActive=True`、`NSWindow.isVisible=True`、`geometry()` 也对，就是画面上什么都没有。**别用 `isVisible` / `isOnActiveSpace` 当判据**，它们反映的是 AppKit 视角，不等于"有没有被合成到那块屏"。唯一可靠的验证是看那块屏的像素有没有变，或者直接用眼睛看。
- **抓屏本身不受 Space 影响**：一度怀疑 mss（走 `CGWindowListCreateImage`）在全屏 app 的屏幕上只能拿到桌面 Space 的旧缓存 —— 依据是「间隔 2 秒两次抓屏像素变化量只有 0.003」。**实测证明这个推断是错的**：切成 accessory 后完整跑通，全屏屏幕上截到的就是当前画面。那 0.003 只是因为当时屏幕上确实没东西在动。ScreenCaptureKit 不需要。
  教训：**「画面没变」不能证明「抓的是缓存」**，得先确保画面本来就在变，这个观测才有意义。
- **多屏窗口别用 `Qt.Tool`，会自己跑到别的屏幕上** ⚠️ 阶段 1 实际踩到的最坑一条。
  `Qt.Tool` 在 macOS 上属于「工具窗口」，会跟着 app 的活动 Space 走。表现极具迷惑性：窗口**刚显示的 100ms 内位置是对的**，大约 400ms 后被系统悄悄挪到当前显示器上。后果是副屏的遮罩叠到主屏、**钉好的参考图过一会儿自己飞到另一块屏**——对这个工具是致命的。
  试过 7 种标志组合，只有 `Qt.Window`、`Qt.Popup`、`Qt.Window | Qt.BypassWindowManagerHint` 能留在原地。代码里用的是 **`Qt.Window`**。代价是浮窗会在程序坞/调度中心占个位置（这正是当初想用 `Qt.Tool` 避免的），但比起图会乱跑，完全值得。
  怎么自查：显示窗口后**等 1 秒以上**再读 `geometry()`，只等几十毫秒会被骗过去。
- **mss 的坐标单位随平台变，不能按 `devicePixelRatio` 硬算**：直觉上会以为「Qt 用逻辑坐标、mss 用物理像素，乘以 dpr 就行」——**实测是错的**。macOS 上 mss 用的就是逻辑点，和 Qt 完全一致（缩放比 = 1，哪怕 Retina 屏 dpr = 2）；Windows 上 mss 才用物理像素。按 dpr 去乘，Mac 上坐标会整个错一倍。
  `overlay.py` 的做法是**运行时实测**：用「mss 报的屏幕尺寸 ÷ Qt 报的屏幕尺寸」现算缩放比，不依赖任何平台假设，Windows 的 150% 缩放也能自动适配。
- **mss 在 Retina 屏上拿不到原生分辨率**：整块内置屏 mss 只能抓到 1512×982，实际是 3024×1964 —— **细节丢一半，参考图偏糊**。Qt 自带的 `QScreen.grabWindow` 能拿到完整的 3024×1964（两者截的是同一块区域，实测内容差异 0.04/255）。`overlay.py` 顶部的 `CAPTURE_BACKEND` 可在 `"mss"` / `"qt"` 之间切换，画画看参考建议用 `"qt"`。
- **多显示器**：每块屏幕单独建一个遮罩窗口 —— macOS 的「显示器各自独立空间」不允许一个窗口横跨两块屏。**当前限制**：一次框选只能落在一块屏幕内，不支持跨屏拖选。
- **选框宽高别用 `QRect(起点, 终点)`**：这个构造函数的坐标是闭区间，正着拖和反着拖算出来的尺寸会差 2 像素。要用「左上角 + 宽高」的写法。
- **截图前必须先把遮罩藏掉**：不然截下来的是蒙了一层灰的画面。代码里是「隐藏遮罩 → 等一帧 → 再抓屏」，那个短延时不是凑数的，是等系统真的把遮罩擦掉。
- **macOS 要给「屏幕录制」权限**：首次运行会弹窗要求授权，在 *系统设置 → 隐私与安全性 → 屏幕录制* 里勾上你运行程序的那个 app（终端 / VS Code / Python）。**没授权不会报错**，只会截到桌面壁纸而拍不到其他窗口 —— 很容易误判成代码有 bug。授权后要重启那个 app 才生效。
- **`IMKCFRunLoopWakeUpReliable` 报错可以无视**：macOS 输入法框架的噪音日志，Qt / Python 图形程序普遍会打，和代码无关，不影响功能。
- **拖动要自己实现**：无边框窗口没有系统标题栏，拖动逻辑靠记录鼠标相对位置来算（阶段 1 已包含）。
- **实时调色的性能**：图很大时，每拖一下滑块都重算整张图可能会卡。先用 numpy 向量化运算（够快了），真卡再优化。
- **色相运算要在 HSV 空间做**：调色相不是直接改 RGB，要先把图从 RGB 转到 HSV，转好色相再转回 RGB。这个到阶段 2 会具体展开。

## 8. 总结

这个项目的聪明之处，在于**克制**：只锁定 Windows + Mac 两个平台、只做「截图 + 置顶 + 调色」这一件事，用你最熟的 Python 落地。
